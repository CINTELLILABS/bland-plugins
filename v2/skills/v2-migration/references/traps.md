# Migration trap catalog

Every row below is a real failure from a production migration. Read all of them before authoring; re-check the relevant ones before pushing. Written for authors working from raw JSON with no platform source access.

| Wrong belief | Reality |
|---|---|
| "v1 route rows translate 1:1 into one v2 rule" | v1 FLAT condition rows on a route are **OR**; only `isGroup` blocks are AND. Collapsing flat rows into one AND'd rule produces impossible conditions (`x<91 AND x>179`) → a hard no-match crash at runtime on the SUCCESS branch. Author one v2 rule per flat row; one rule per isGroup block. |
| "Fallbacks can be omitted when the rules look exhaustive" | A route whose rules don't match and whose `fallbackNodeId` is empty hard-fails the call for that caller. Carry the v1 fallback verbatim; keep it empty ONLY when v1 itself had none (then document the carried defect). Cross-flow fallback targets (outside the scenario) point at the flow's end pill so the hub handles the hand-off. |
| "Cross-scenario exits can share an end edge" | Merging two intents into one exit label ("DNC / not the patient") starves the hub of the intent and misroutes both. One end edge PER distinct exit label, each carrying its own description. |
| "The hub can be told to stay silent / run code first" | The hub is generative and waits for the caller. Pre-speech logic needs a silent bootstrap scenario and the `inbound` edge re-pointed at it. |
| "Hub hard rules can gate globally on identity" | An unqualified "unverified → identity scenario" bounces wrong-number callers, third parties, and do-not-call demands back into the greeting forever. Scope identity gates to the content they protect and list always-enterable scenarios explicitly. |
| "Attached tools carry 1:1" | A v1 node tool of `type:"code"` (`config = {snippet_id, snippet_version, response_data, responsePathways}` — no tool_id, no inline code) **cannot be expressed as a v2 attached tool** (`toolType` is only custom_tool/track). A naive carry produces a hollow tool that never executes — and sims won't catch it if the lane is gated (e.g. CRM-found only). Re-represent: `customCode` step with the same pin and an explicit `variables` input map (code steps feed the snippet ONLY the mapped inputs; the v1 tool lane sent all call variables) + a `route` step carrying the responsePathways rows as rules + fallback + mirror edges. Then grep the FINAL snapshot for every source snippet id — pin presence is a release gate. Known deltas: fires on traversal (one turn later); first run passes unresolved `{{state}}` literals for round-trip counters (verify nothing routes on or interpolates them); snippet failure falls to the route fallback. |
| "responsePathways field names mean what they say" | The naming is skewed: `label` = trigger variable, `variable` = operator, `condition` = value. Author in the skew or the rows silently never match. |
| "Node-scoped KB can be lifted to agent-level knowledge" | Agent-level knowledge becomes a call-wide KB tool on every step — scripted steps start answering from KB instead of their script. Lift only when v1 semantics were genuinely call-wide. |
| "Sims failing = the migration is broken" | Time-gated branches (after-hours), lookup-gated branches (CRM not-found), and tester personas that can't complete the flow (no account number, can't confirm a checklist step, asks the probe question after the flow already transferred) all fail sims with a correct agent. Read the engine trace, classify harness-artifact vs judge-flake vs routing-flake vs real bug, and fix in the right layer. |
| "One sim run per scenario is a verdict" | LLM judges flip run to run. 3 reps on any flapper; weigh the judge's reasoning text over its pass/fail bit; final bar is a full-suite sweep green on ONE head version. |
| "Web-chat tests resolve built-in clock variables" | They don't — `{{now_utc}}` arrives as the literal string, date parsing nulls, and every clock-derived flag goes false. Put a real timestamp in request data (format like "Monday, September 14, 2026 3:00 PM"), full-call-scoped so every clock in the call agrees. |
| "The SMS preview endpoint is the agent test chat" | It runs the SMS pipeline; a voice agent's silent entry chain never advances there. Use the real test-chat WebSocket (see the v2-testing skill). |
| "Sim expectations should encode ideal behavior" | They must encode V1'S OWN behavior — including its quirks. An assertion that demands something v1's topology never offers (e.g. scheduling for an unrecognized caller when scheduling is lookup-gated) fails a correct migration. Carry defects bug-for-bug and note them in the report. |
| "GUI HTTP clients can push big snapshots" | Multi-hundred-KB JSON bodies get mangled (newline corruption, unresolved file refs). Push from a real terminal with the minified single-line file, or through the MCP passthrough with a native JSON object body. |
| "The export's secrets are placeholders" | They are live credentials. Never print them, never move them into new configs in plaintext, and flag rotation to the owner (plaintext auth headers in v1 configs are common). |
| "Testing is safe because it's 'just chat'" | Webhooks and code snippets FIRE for real in chat sims: CRM lookups hit the real CRM, schedulers post real events, gate-openers open real gates. Before any test: classify every integration read vs write, run reads with synthetic data, and gate every write branch behind personas that stop short + explicit customer sign-off for one coordinated smoke. Transfers are inert in chat but dial real lines on voice. |
| "The customer's test fixtures are valid" | Test-config request data goes stale: a QA tenant key can 404 in prod config, and a fixture can belong to a DIFFERENT product variant (a tenant that is not on the integrated product has no credentials for it — the bootstrap "succeeds" but downstream tools get empty ids). Symptom cluster: generic greeting with a blank name, tools erroring on empty parameters, fallback transfers everywhere. Before grading ANY agent behavior, verify the fixture actually hydrates (trace the bootstrap's own debug/HTTP calls), and find the fixture the customer's own suites use for THIS pathway — group their existing scenarios by target pathway and copy that request data. |
| "A repeated v2 sim failure means a v2 bug (or: means nothing, sims flake)" | Neither, until you run the DIFFERENTIAL: clone the exact scenario (same persona, judges, request data) onto the v1 pathway and rep both 3×. v1 solid + v2 failing = real regression, fix v2. v1 failing with identical texture = inherited variance — tighten the judge to v1's real bar and document the rate; "fixing" it in v2 means silently diverging from the source. Both verdicts occurred in production migrations. |
| "A conduct regression can be fixed with a prompt rule" | Sometimes it can't: a v2 in-flow step that replaced a v1 silent-router GLOBAL fabricated phone numbers 4 runs straight THROUGH escalating hard-rule appends (5 distinct invented numbers; v1 baseline 3/3 correct). The fix was the CONSTRUCT: make the step a static "." pill (nothing to fabricate), move extraction rules into the variable descriptions (that's what the extractor reads), and restrict the speaking step to the exact {{variable}}. When prose fails twice, change the mechanism, not the wording. |
| "Guard rules are free" | An unscoped guard leaks: "never book after a deferral — acknowledge and close politely" made the agent CLOSE EARLY on availability-revision conversations. Scope every guard to the exact moment it protects ("applies ONLY at the final booking moment; never prevents checking availability") and re-run the lanes adjacent to it. |
| "The model won't fabricate tool arguments" | It booked a real appointment after an explicit deferral by passing a fabricated caller_confirmation to the booking tool. For any write-capable tool, the gate variable needs a step-level rule tying it to the caller's LAST turn — and the sim suite needs a probe that tempts exactly this. |
| "Judge PASS/FAIL statuses are the verdict" | On a fixed head, a 25-scenario suite oscillates several points run-to-run: judges invert criteria ("failed: agent gave a specific dealership name rather than a generic greeting" — the criterion asked FOR the dealership name), hallucinate ground truth ("does not match the known parts number" — the judge cannot know it), and fail correct fallbacks (transfer after a live upstream API error). The record is: one full green sweep on one head + every flapper classified from its engine trace + inherited-variance rates from v1 baselines. |
| "Write-side test bookings clean themselves up" | Every booking a sweep creates is real. Drain after EVERY sweep with the customer's own cancel utility, verify at tool level (success:true / none-found), and know the failure mode: cancel lookups can lose vehicle-row attribution on multi-vehicle test accounts, leaving an appointment no lane can find — record its exact date/time/name so the customer can purge it directly. Use an obviously-synthetic persona name so anything left behind is identifiable as yours. |
